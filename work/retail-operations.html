Retail Operations Analytics

The business question

Retail decisions often cross several operational areas. A revenue increase may coincide with weaker margin, and supplier delays may affect both stock availability and the customer experience. This project explores those relationships within a model multi-store retailer.

A connected reporting model

The project starts with synthetic operational files and a normalized PostgreSQL schema. SQL views and Python transformations create tables ready for business-intelligence reporting.

  • Modeled customers, stores, products, suppliers, orders, shipments, returns, and inventory.
  • Used CTEs, window functions, constraints, reconciliation queries, and indexes.
  • Defined a Power BI star-schema model and dashboard specification.
  • Included an Excel dashboard workbook covering five areas of retail performance.

What the project produced

The repository connects source data, relational tables, analytical queries, BI-ready outputs, and visual reporting. Its workbook includes executive reporting, sales and profitability, inventory operations, customer analytics, and supplier and delivery performance.

This provides a concrete example of translating operational questions into data structures and repeatable measures.

How to interpret it

This is a portfolio project using synthetic data. Its figures demonstrate analytical methods and are not results from a live retailer.

The repository includes a Power BI model and dashboard specification; the included interactive dashboard deliverable is an Excel workbook.
